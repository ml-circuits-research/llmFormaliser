SOP LANG / PHASED TASKS / BATCHING

Selective single-pass repair

Separate task types preserve the baseline formalizer prompt and add one repair attempt.

Index

begin (batch) → toCnl (individual) → judge (batch when needed) → review (individual). A failed candidate enters repair (batch), then conversion and selective judging again. finish writes every attempt. Repair is limited to one pass per case. Its separate repair tier can select a different model with --repair-provider and --repair-model; the judge remains unchanged before and after repair.

Local structural or numeric problems skip the initial judge and become repair feedback. Valid semantic differences include the judge’s specific feedback. Inconclusive or malformed judgments do not trigger speculative rewriting. Successful cases skip repair.

Exact source/CNL pairs can reuse a prior valid judgment only with the same model, judge prompt and validator. Conflicting cached judgments are excluded. Unchanged repaired candidates reuse their own previous judgment. Lexical coverage alone never establishes equivalence.

Baseline and repair scores are reported separately; raw attempts and feedback remain in the run artifacts. Dictionary-based selection restrictions are not yet implemented.

Domain-specific prompts and converters live in llmFormaliser. Ploinky Workers remains a generic phased executor.
